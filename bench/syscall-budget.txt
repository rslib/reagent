# Syscall budgets for the fixed reagent runs of bench/syscalls.sh, one line
# per scenario and group: <scenario> <group> <max>.
#
# linux-x86_64 only: the counts are those of the Linux build of reagent, so a
# budget means nothing on another OS or architecture.
#
# Each line is, per scenario and group, the highest count of N runs times 1.15,
# rounded up and at least 48 over that count, from bench/syscalls.sh
# --measure N. Use at least the
# default ten: the threads a run makes with the tokio blocking pool vary
# with timing, and a small sample can miss the high count, which a later run
# would then be over.
#
# The groups are io, wait, fs, mem, proc and other, plus a total. The other
# group holds every syscall no group names.
# made from 50 runs on linux-x86_64 after durable sessions: each line is the
# higher of the --measure budgets of 20 and 30 runs. Every run now saves its
# session (a writer thread, the part file, a sync at each turn end and before
# each side-effect tool, and the session list), about 160 to 180 syscalls
# more per run than before. Find and grep make from 0 to about 11 more
# blocking threads from run to run, so their proc and mem lines are wide.
# The worker writes its discovery entry once more per run, when the run
# starts (state working, for the Herdr Inbox): 4 fs syscalls more per run,
# 6 for grep, measured on linux-x86_64; each fs line rose by that much.
# find fs: 303 to 317 over 8 runs (the high ones right after the suite), so 320.
# A run looks for two skills folders (the config one and the project's
# .agents/skills), one fs syscall each even when it is missing: each fs line
# that was at its count rose by 2, measured on linux-x86_64.
# Re-made 2026-11-13 from --measure 10 on linux-x86_64, because the wait,
# total and find fs lines moved from run to run. Every line is the measured
# budget except the fs lines of the other scenarios, which do not move from
# run to run and stay at their exact count, so a small fs change still fails.
